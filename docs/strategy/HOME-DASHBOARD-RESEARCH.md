# Home Dashboard Research: how ~100 products show "all my projects"

*Prepared 10/28/2026 for the RunF9 Home page redesign.*

## 1. Method

- **Scope:** 100 products in three groups: construction and scheduling (35), general project and work management (35), and widely admired dashboards and "list of things" home pages (30).
- **Verified (V):** For 16 products I checked current help-center pages, docs or changelogs through web search: Procore, Autodesk Build, SmartPM, Oracle Primavera Cloud, Asana, Linear, Vercel, monday.com, Buildertrend, Microsoft Project for the web, Datadog, Smartsheet, and partly Figma (user forum only), Fieldwire, Nodes & Links and Schedule Validator (third-party listings only; the pages did not describe their layout).
- **General knowledge (G):** The other 84 rows come from my general knowledge of these products. Treat them as typical rather than checked, because interfaces change often. I could not find Touchplan documentation at all.
- **No made-up numbers:** This report contains no usage statistics or quotes. Where it says "most" or "common", it means a count across the table below.

## 3. Recurring patterns (most to least common)

1. **Search, filter, sort.** Found in nearly every product. The better ones keep only search visible and put filters in one menu (Linear, Vercel, Asana). Saved views exist in Procore, Linear, Salesforce, HubSpot and Zendesk.
2. **One item per thing, with history inside it.** No product in the sample lists each version or update as a separate top-level item. Procore stores schedule versions inside the project. SmartPM shows each upload as a new version in the project's Schedules tab. Vercel shows one card per project with the latest deploy on it, and the full deploy history one click deeper. Google Drive and Figma keep version history inside the file.
3. **Default sort by recent activity.** Vercel sorts by activity, and Figma, Drive, Airtable, Notion and Microsoft Project start from recents. Portfolio tools (Asana, Procore) sort by name or by a saved view.
4. **Favorites or recents.** Procore, Microsoft Project, Datadog, Jira, Trello, Airtable, Drive, Power BI and Grafana all have them. Microsoft Project puts favorites above everything else.
5. **Status signal per item.** It is usually one colored word or dot with three states (on track / at risk / off track): Asana, Linear, monday.com, Smartsheet, Teamwork. Vercel and Render use one status dot. The calm products show one signal per item, not several.
6. **Table versus card toggle.** Vercel, Google Drive, Figma, Procore, Notion and Basecamp have one. Card view is usually the default for small sets and table view for large ones. Vercel saves the choice per account.
7. **Summary strip.** SmartPM shows counts (delayed, low quality, needing a new schedule, on track), and clicking a count filters the list. Apple Home, Stripe, Zendesk and Asana's Progress tab do similar things. The best strips have three to five numbers that are also filters.
8. **"Needs attention first."** This is less common as a default, but strong where it exists: SmartPM's delayed and stale counts, Linear's "At risk" saved views, Zendesk views with counts, and Autodesk Build's overdue Work Status card.
9. **Empty states.** From general knowledge, the admired products (Linear, Vercel, Notion, Airtable) show one sentence and one primary button, sometimes with a template or sample. Enterprise tools often show a bare empty grid.

## 4. Answers to the founder's questions

**(a) One entry per project, or one per upload?** One entry per project. Every product in the sample groups versions under the parent item, and the closest competitors (SmartPM, Procore, Acumen, Schedule Validator) treat each upload as a version of a project. Listing every upload would turn 30 projects into 300 rows, and the same project name would repeat, which is the "getting lost" problem users already report. Show the latest update's data on the card, plus a small "Baseline + 7 updates" note. Keep the full history on the project page as a timeline.

**(b) Should built-in-app schedules sit with uploaded ones?** Yes, on the same dashboard. Users think in projects, not in how a file was made. Show the source as a small, quiet label ("Built in RunF9", "P6", "MS Project") and allow a filter on it. Drafts that are not finished could appear with a "Draft" status, so that unfinished work cannot pass for a real schedule.

**(c) Which fields matter most?** This ranking comes from scheduling practice and from what SmartPM, Primavera Cloud, Smartsheet and P6 show. I did not survey users.
1. **Project name** (plus an optional number or client).
2. **Forecast finish against the required (contract) finish**, shown as a **variance in days**. This is the question executives and owners' reps ask first.
3. **Status** (on track / at risk / late), worked out from the variance and the trend.
4. **Data date / last update.** This tells you whether the information is current. A schedule that has not been updated in over 30 days is itself a warning; SmartPM flags exactly this.
5. **Schedule quality score.** Schedulers and owners' reps care a lot; executives less. Show it as a grade.
6. **% complete.** Useful, but it can mislead, so keep it secondary.

Put these on the project page instead, or in table view only: start date, critical activity count, and number of updates. They matter to schedulers, but they add noise on a portfolio card.

## 5. Recommended design for RunF9 Home

1. **Header:** "Projects" title, firm name, and one primary button: "New project" (with Upload schedule / Build with interview inside it).
2. **Summary strip (four numbers, each a filter):** Late · At risk · Needs update (more than 30 days old) · On track. Clicking one filters the list; clicking it again clears the filter. Show no money, no totals of activities and no charts here.
3. **Needs attention first:** If any project is late, at risk or stale, show a short "Needs attention" group (at most 5, then "Show all") above the full list. If there are none, hide the group completely rather than showing an empty box.
4. **Main list, cards by default for 12 or fewer projects, table by default above that;** a toggle that saves the user's choice.
5. **Card fields (five at most):** name and source label; status pill; forecast finish with variance ("Jun 14, 2027 · 12 days late"); data date ("Data date 10/01/2026"); a small "Baseline + 6 updates" line. Optional: quality grade as one letter.
6. **Table columns:** Name · Status · Forecast finish · Variance (days) · Required finish · Data date · % complete · Quality · Updates. Every column is sortable, and users can hide columns.
7. **Default sort:** By attention: late (largest slip first), then at risk, then stale, then the rest by most recent update. Other options: name, forecast finish, last updated.
8. **Controls:** Search box always visible; one "Filter" menu (status, source, PM, tag); star favorites, with favorites pinned at the top; "Show archived" is off by default.
9. **Opening a project:** The whole card or row is clickable and opens the project page. That page holds the update timeline (baseline, then each update), the comparison between updates, and the details of the selected schedule that the current Home shows.
10. **Empty state:** One sentence ("Add your first project") with two choices: Upload a P6/MS Project file, or Build one with the interview. If possible, include a sample project the user can open.
11. **Motion and interactivity:** Keep it quiet. Use a 150–200 ms fade or rise on hover and on filter changes, and keep a small skeleton visible while loading. Cards should not jump around. Do not animate numbers counting up. Honor the "reduce motion" setting. The whole page should work by keyboard (focus rings, Enter to open).
12. **Visual tone:** Lots of white space. Use status color only in the pill and the variance text. Use the `warm-*` text tokens for AA contrast and MM/DD/YYYY dates.

**Anti-patterns to avoid:**
- Listing every upload as its own item.
- More than five numbers on a card, or several colored badges for one project.
- Mini Gantt charts or sparklines on every card. They are noisy at 50 or more projects; save them for the project page.
- An empty "Needs attention" box saying "0".
- Splitting app-built and uploaded schedules into separate pages.
- Showing % complete as the main progress figure. Finish-date variance matters more.
- Sort or view settings that reset each visit. Figma users complain about this in its forum.
- Faint grey text and any date format other than MM/DD/YYYY.
